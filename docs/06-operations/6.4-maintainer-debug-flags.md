# 6.4 Maintainer Debug Flags

*Last Updated: 2026-06-16*

> Env-var-controlled toggles for gateway maintainers. Not surfaced in `config.toml`, not surfaced in CLI `--help`, not announced to operators. Each one re-enables a code path the default product surface deliberately excludes.

By default the gateway captures only the user-facing conversation shape from each source — the parent transcript / parent bubbles / shallow sub-agent envelopes. Sub-agent intermediate turns and the noisier KV namespaces are filtered out because they are noise relative to the rendered conversation.

Maintainers debugging gateway behavior need a way to re-enable the deeper capture per source. The flags on this page are that escape hatch. They are read once at process start and a daemon restart is required to take effect.

There is a second, complementary maintainer surface: a set of **god-mode CLI commands** that stay hidden from `--help` unless dev mode is active. The env flags above gate *what the daemon captures*; the god-mode commands gate *which debugging tools the CLI exposes*. They are documented together at the bottom of this page because both are deliberately omitted from the operator-facing surface.

## All flags

| Env var | Default | Effect when set truthy |
| --- | --- | --- |
| `PROXAI_GATEWAY_CAPTURE_SUB_AGENTS` | `false` | Global override. If truthy, every source behaves as if its per-source flag is set. |
| `PROXAI_GATEWAY_CAPTURE_SUB_AGENTS_CLAUDE_CODE` | `false` | Adds the `*/*/subagents/*.jsonl` pinned-depth glob back into Claude Code discovery. Sub-agent JSONL files are shipped alongside parent transcripts. |
| `PROXAI_GATEWAY_CAPTURE_SUB_AGENTS_CODEX` | `false` | Disables the `thread_spawn_edges` pre-fetch filter on Codex rollout discovery. Child-thread rollouts pass through alongside parent rollouts. |
| `PROXAI_GATEWAY_CAPTURE_SUB_AGENTS_CURSOR` | `false` | No-op today. Wired and resolved, but Cursor's row-selection SQL does not branch on it. |
| `PROXAI_GATEWAY_CAPTURE_SUB_AGENTS_CLAUDE_DESKTOP` | `false` | No-op today. Wired and resolved, but `discoverClaudeDesktopFiles` does not branch on it (Claude Desktop persists no separate sub-agent artifacts the gateway can discover). |
| `PROXAI_GATEWAY_CAPTURE_SUB_AGENTS_GEMINI` | `false` | No-op today. Wired and resolved, but `collectGeminiConversation` does not branch on it (Gemini capture always includes trajectory steps and metadata). |

## Truthy parsing

`parseBool(value)` accepts case-insensitive `1`, `true`, or `yes` as truthy, after trimming whitespace. Anything else — unset, empty, `0`, `false`, `no`, `maybe`, `off`, `enabled` — resolves to false. No clever heuristics, no synonyms beyond those three.

## Resolution semantics

For a given source `S`:

```
effective(S) = parseBool(env.PROXAI_GATEWAY_CAPTURE_SUB_AGENTS)
            || parseBool(env.PROXAI_GATEWAY_CAPTURE_SUB_AGENTS_<S>)
```

Set the global flag truthy and every source captures. Set only a per-source flag and only that source captures. The global flag does NOT need to be falsy for a per-source flag to take effect — they OR together.

The resolution runs once at module load and produces `SUB_AGENT_CAPTURE_BY_SOURCE: Record<SourceApp, boolean>` in `services/config/sub-agent-flags.ts`. Every per-source discovery / collect function consults this constant. Restart required to change.

## Per-source behavior

### Claude Code

Default: only the parent glob `*/*.jsonl` runs.

Flag on: the second glob `*/*/subagents/*.jsonl` runs alongside the parent. Sub-agent JSONL files (one per `Task` tool invocation in a session) are each given a `source_cursors` row with their own `source_path_hash` and shipped via the same byte-range pipeline as parent transcripts.

Receiver behavior: nest's `ClaudeCodeExtractChatsService` composes a composite `chat_id = sessionId:agentId` for sub-agent records (the `agentId` field is in every sub-agent JSONL line), and writes `agent_call_records` rows with the appropriate `agent_id`. Discovery is gateway-only — when the flag is on, this works end-to-end with no nest changes.

### Codex

Default: `discoverCodexRolloutFiles` pre-queries the highest-numbered `state_*.sqlite` via a JOIN of `thread_spawn_edges` and `threads`, builds a `Set<string>` of child rollout paths (`threads.rollout_path` is the absolute on-disk path), and skips any discovered rollout file whose path is in that set. Errors opening or querying the state sqlite are caught and produce an empty set (fail-open) — the filter never blocks rollout capture.

Flag on: pre-fetch + filter are skipped. Every rollout file under `sessions/YYYY/MM/DD/rollout-*.jsonl` is discovered, including child-thread rollouts.

The `thread_spawn_edges` table is captured via the state-table source regardless of the flag — parent → child linkage always reaches nest. The flag only controls whether the child's conversational content is shipped.

### Cursor

Cursor's row-selection SQL does not branch on this flag:

```sql
WHERE rowid > ?
  AND (key LIKE 'composerData:%'
       OR key LIKE 'bubbleId:%'
       OR key LIKE 'agentKv:blob:%')
ORDER BY rowid ASC
```

`buildCursorSelectRowsSql` accepts the flag as an unused parameter; `SELECT_ROWS_SQL_BASE` and `SELECT_ROWS_SQL_WITH_SUB_AGENTS` are identical strings, and `selectCursorSql` returns the same SQL either way. Setting `PROXAI_GATEWAY_CAPTURE_SUB_AGENTS_CURSOR` resolves into `SUB_AGENT_CAPTURE_BY_SOURCE.cursor` but changes nothing the gateway captures.

The three captured prefixes — `composerData:`, `bubbleId:`, `agentKv:blob:` — are selected on every Cursor capture. The other `cursorDiskKV` prefixes (`composer.content.`, `checkpointId:`, `ofsContent:`, `inlineDiff:`, `codeBlockPartialInlineDiffFates:`) hold file-edit snapshots and inline-diff UI state; they are not selected, and the flag does not add them.

### Claude Desktop

No-op today. `discoverClaudeDesktopFiles` takes no `captureSubAgents` option and does not branch on the flag. The flag still resolves into `SUB_AGENT_CAPTURE_BY_SOURCE['claude-desktop']`, but Claude Desktop's Cowork sessions persist the orchestrator/sub-agent turns inline in the same `audit.jsonl` the gateway already captures — there is no separate sub-agent file to gate. If a future desktop layout starts persisting deeper artifacts, the branch would land in `discoverClaudeDesktopFiles` and the flag would begin gating it.

### Gemini

No-op today. The flag still resolves into `SUB_AGENT_CAPTURE_BY_SOURCE['gemini']`, but `collectGeminiConversation` does not branch on it. The gateway captures all trajectories, steps, and metadata in the database without separate gating.

## Volume impact

Rough byte cost when a flag is turned on, based on one developer laptop:

| Source | Default capture (bytes / `state.vscdb`-equivalent) | With flag on | × baseline |
| --- | --- | --- | --- |
| Claude Code | ~290 MB parent transcripts | ~570 MB (+ sub-agents) | ~2× |
| Codex | parent rollouts only | + child rollouts (only when `agent_jobs` feature is in use) | ~1× on idle, larger when used |
| Cursor | unchanged | unchanged | 1× |
| Claude Desktop | unchanged | unchanged | 1× |
| Gemini | unchanged | unchanged | 1× |

The buffer's 50 GiB soft-pause cap (locked 2026-05-06) governs total buffered volume. Turning on the Claude Code or Codex flag on a busy machine adds sub-agent transcript volume; if uploads cannot drain it fast enough, operators see `buffer_soft_pause` events and pacing slowdowns, not data loss.

## God-mode commands hidden from `--help`

A second class of maintainer surface lives in `main.ts`: developer commands that are registered with `{ hidden: !godMode }`, so they vanish from `proxai-gateway --help` unless dev mode is active. `godMode` is computed once at boot from the root dev-mode flag:

```
const godMode = await readDevModeSentinel(join(profileRootDir(), 'DEV_MODE'));
```

`readDevModeSentinel` returns `true` only when the `DEV_MODE` file exists *and* its stored `bootId` equals the current `readBootId()` value. After a reboot the boot id no longer matches, the file self-clears, and `godMode` is `false` — so the developer commands disappear from `--help` again until the next `dev on`. The full profile/dev-mode model is documented in [6.5 Dev Mode and Profiles](./6.5-dev-mode-and-profiles.md).

| Command | Hidden when | Purpose |
| --- | --- | --- |
| `run` | `{ hidden: true }` — **always hidden** | Foreground daemon entrypoint invoked by the service unit; never run by hand. Not gated on dev mode because it is never an operator command in any mode. |
| `rescue` | `{ hidden: true }` — **always hidden** | Rescue/restart the daemon if it is wedged or crashed. Not gated on dev mode because it is an automated fallback check. |
| `dev [action] [key]` | `{ hidden: !godMode }` | Manage dev mode: `dev on`, `dev off`, `dev setup <KEY>`, or no action to toggle. This is the one god-mode command an operator can still invoke blind (it is how you *enter* god mode). |
| `xstate` | `{ hidden: !godMode }` | Run the daemon in the foreground with the Stately browser visualizer. Also re-checks `godMode` at action time and refuses to run with an error if dev mode is off. |
| `inspect` (alias `ins`) | `{ hidden: !godMode }` | Dry-run telemetry scanner: compiles record/file counts and decompressed sizes without touching buffers. |
| `tail` (alias `t`) | `{ hidden: !godMode }` | Stream NDJSON log entries from the active profile's log file. |
| `redaction` (+ `redaction test`, `redaction list`) | `{ hidden: !godMode }` | Inspect on-device redaction rules and dry-run them against a local file. |
| `replay <logPath>` | `{ hidden: !godMode }` | Replay a JSONL log of state-machine transitions and print the final state per machine. |

Everything else — `setup`, `start`, `stop`, `restart`, `status`, `uninstall`, `upgrade`, `logs`, `doctor` — is always visible regardless of dev mode.

Hidden does not mean disabled: a hidden command is still dispatchable if you type its name. `{ hidden: true }` only removes it from the generated `--help` listing. The one command that additionally hard-gates its body is `xstate`, which re-reads `godMode` and exits with an error message pointing you to `proxai-gateway dev on` when dev mode is off.

## What is intentionally NOT in this doc

- README mentions — gateway README is operator-facing; these flags are not.
- CLI `--help` output — `proxai-gateway --help` and subcommand help do not list these vars.
- `config.toml` schema — the validator does not know about these. Adding them to `config.toml` will produce no effect; only env vars are read.
- Code comments — the source code itself does not annotate these flags. Their presence is intended to be discovered by reading this doc, not by grepping the source.

## How to verify a flag is in effect

The gateway emits no startup line confirming flag values today. Two indirect signals:

- **Claude Code**: with the flag on, `tail --level=debug` shows `capture.discovered` entries for paths matching `*/subagents/*`.
- **Codex**: with the flag on, `tail --level=debug` shows `capture.discovered` for rollout files whose `thread_id` matches a `thread_spawn_edges.child_thread_id` value (cross-reference manually via the state sqlite).
- **Cursor**: no observable difference (no-op).
- **Claude Desktop**: no observable difference (no-op).
- **Gemini**: no observable difference (no-op).
